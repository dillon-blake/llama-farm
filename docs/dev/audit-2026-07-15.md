**The three live bugs the oracles caught** (all with a falling loss, all passing the per-op MODE_GRAD
checks — each caught only by a per-tensor float64 oracle at effective LoRA scale ≠ 1, the S1-38 lesson):

1. **S1-41 / `41141dd4f`** — `ggml_compute_forward_soft_max_ext_back_f32` not in-place-safe onto
   `src1`; a Mixtral router aliases `dst` onto the softmax output `y`, so `d_logits≈0` and every LoRA
   upstream of an MoE block trained on a gradient wrong by 5–25 %.
2. **S1-47 / `555c44643` (a)** — `ggml_ssm_scan_back` recomputed intermediate states from the
   recurrent-state cache the forward had overwritten in place; every Mamba layer but the last trained
   on a corrupted scan gradient (`dx`, `ddt`, `dB`, `dC`).
3. **S1-47 / `555c44643` (b)** — the Mamba conv's VIEW-backward handed `ggml_acc` a non-contiguous
   grad, aborting *every* Mamba training graph at backward before it could print a loss.

## THE LIVE BUG (S1-41)

ggml's analytic gradient on the MoE fixture is wrong by ~5–25 % relative for every LoRA
parameter upstream of an MoE block. Proof: the float64 MoE oracle self-audits green, matches
ggml's forward at 1.2e-07 at step 0, and a finite difference of the *real ggml graph* sides
with the oracle against ggml's own backward. Invisible to MODE_GRAD (per-op), `test_moe`
(loss falls anyway) and the S1-03 FD gate (dense fixture only). Root-cause/fix in progress in
the fork.
